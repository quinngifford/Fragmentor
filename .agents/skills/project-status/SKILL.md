# Project Status

Read `STATUS.md`, but do not blindly trust it.

Inspect the current repository and relevant tests/configuration so the report is based on the project as it exists now rather than assumptions from previous conversations.

Determine:

- what currently works
- what is incomplete
- what is broken or uncertain
- what is currently being worked on
- what verification has or has not happened
- the safest useful next step

For unfinished items, explain what "unfinished" means in practical terms rather than only naming technical components.

If `STATUS.md` is stale or incorrect, update it to match current reality.

Keep `STATUS.md` concise. It should be a current snapshot, not a chronological development log.

Explain the resulting status to the user in simple language.
