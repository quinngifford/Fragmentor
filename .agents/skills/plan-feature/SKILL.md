# Plan Feature

Use this skill for substantial work, not routine small changes.

Inspect the relevant code and project state first.

Briefly explain:

- what needs to change
- the approach you plan to take
- what parts of the project are affected
- important unknowns, risks, or decisions
- how the result will be verified

Keep the plan concise and easy for the user to understand.

Do not create architecture or abstractions merely because planning revealed possible future needs.

Prefer the smallest solution that satisfies the current requirement cleanly.

If multiple substantially different approaches are genuinely worth testing, identify that clearly and consider using the version-control workflow to preserve a shared checkpoint before experimenting.

If implementation was requested, proceed after planning unless a decision genuinely requires the user.
